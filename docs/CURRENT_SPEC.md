## 2. 利用者・ログイン・承認

- Firebase Authentication の Google ログイン。ログイン、ログアウト、ログイン状態監視、リダイレクト復帰処理がある。
- 認可の正本は Firestore の `members/{uid}` の `role`。役割は `admin`（管理者）、`member`（講師）、`parent`（保護者・限定閲覧）。
- `accessStatus/{uid}` はログイン時の役割確認用の補助データであり、権限昇格の根拠にしない。ルールは `members` の役割との一致を要求。
- 未承認の利用者は名前を `userProfiles/{uid}` に登録し、UID を管理者に知らせる。管理者が UID で承認する。講師登録は最大 **10人**（アプリ内の上限判定）。
- 管理者はメンバー承認・役割/表示順等の管理を行う。講師本人は表示名を変更できる。メールアドレスはメンバー一覧に表示しない方針。
- 保護者役割は講師情報をすべて閲覧するための権限ではない。元々、一般保護者向け全面公開ではなく、動作確認用に設けたアカウントという経緯がある。**講師専用情報や子どもの出欠メモを保護者に公開しない。**

### Google プロフィール画像

- `memberAvatar(m)` は Firestore に保存された `photoURL` を表示し、許可された `googleusercontent.com` の HTTPS URL のみ画像として扱う。取得失敗時は名前の頭文字表示。
- 講師がアプリを開いてログイン状態が復元されると、`syncOwnGoogleAvatar()` が Firebase Auth の `reload(me)` 後に Google プロバイダーの `photoURL` を確認し、変更があれば**本人の** `members/{uid}` に保存する。認証画面を毎回強制表示する処理ではない。
- Google/Firebase 側の情報更新に遅れがあれば即時反映されない。実際に画像変更後、再ログインで反映した事例がある。
- スタッフ一覧は `members` のリアルタイム監視により更新される。一方、**保護者向け公開講師画像は別の `parentSchedules/{eventId}/instructors/{uid}` に複製**される。自分の画像同期だけで保護者側の複製も必ず即時更新されるとは断定しない（`syncPublicInstructor` の呼出経路を確認する）。

| 画面 | 管理者 | 講師 | 保護者 |
| --- | --- | --- | --- |
| 今後の活動 | 閲覧・出欠 | 閲覧・出欠 | **公開予定のみ閲覧** |
| まとめて回答 | 自分の出欠 | 自分の出欠 | 非表示 |
| 予定を登録 | 可 | 可 | 非表示 |
| 過去の活動 | 閲覧・条件/CSV | 閲覧・条件/CSV | 非表示 |
| メンバーの管理 | 可 | 非表示 | 非表示 |
| 予定の一括削除 | 可 | 非表示 | 非表示 |

| スタッフ通知送信 | 可（明示ボタン） | 不可 | 不可 |

### 今後の活動・講師向け

- 月別表示。活動カードの上部に日付（曜日を含む）、活動種類、時間、場所、参加者のアイコン。
- 種類と絵文字：`通常活動 🐦`、`あそぼう 🎈`、`忍者 🥷`、`合宿 🏕️`、自由入力 `✨`。
- 場所は `里山`、`ドラマ`、`マルチ`、`パフォ`、`研修室` 等で色分け（`venueClass`）。自由入力も可能。
- 日付表示の曜日/休日色は `dateColorClass` と休日判定を参照。
- **時間と「📝 出欠メモ」ボタンは隣接するが別々の枠**。時間が `終日` の場合も同じ。
- **講師の出欠詳細と出欠メモは独立開閉**。活動カードの開閉操作で講師一覧を展開し、メモボタンでメモ欄だけを開く。両方を連動させない。
- 講師の出欠一覧は別の淡色の区画に表示。回答は `○ 参加`、`△ 未定`、`× 欠席`。未回答の未来活動は「未回答」表示と専用アラートあり。
- 自分の出欠を変更できる。予定の内容変更 UI は管理者のみ。過去予定は管理者側で扱う実装がある。**過去の回答変更可否は UI とルールの両方を確認する**。
- 未来/過去の境界は講師側では基本的に日本日付 `today()`。活動の翌日から過去扱い。

### 子どもの「📝 出欠メモ」

- 講師用のイベント単位の補足情報。子ども本人のアカウント・出欠回答機能ではない。
- Firestore：`events/{eventId}/childMemos/{memoId}`。
- 項目：名前（自由入力、1～40文字）、区分（`欠席` / `遅刻` / `早退`）、作成/更新時刻。**時間入力欄はない**。
- メモ入力フォームは初期状態で隠し、`＋ 追加する` を押して表示。既存メモの編集・削除に対応。
- 名前は小さめの黒文字（設計上約13px）。区分は欠席=赤、遅刻=オレンジ、早退=青のラベル。削除は `×`。
- 保護者ページには表示しない。Firestore ルールでも `admin` / `member` に限定。
- 重要：一括削除のコードは `answers` と公開講師データを取得・削除しているが、**`childMemos` を明示的に列挙削除する処理は確認できない**。親イベント削除時にサブコレクションが自動削除されると仮定しない。変更時の要調査点。

### 保護者向け「今後の活動」

- **講師用の `events` を直接読ませず**、公開用 `parentSchedules` とその `instructors` から必要な情報だけ取得。
- 読み取り専用。講師の回答一覧、未回答表示、編集機能、子どもの出欠メモはない。
- **活動種類（例：🐦 通常活動）の横に小さい時間表示**（現行 CSS では 12px）。日付・活動名・時間をコンパクトに配置。場所バッジを表示。
- 未来の活動に確定参加講師（`○`）のアイコン・名前を表示。未確定ならその旨を表示。
- 予定は `dateAt` を使って **活動日当日 23:59:59（日本時間）まで**閲覧対象。保護者画面はページ読み込み時のスナップショット取得で、常時リアルタイム購読しない。新しい公開予定を確実に見るには再読み込みする。
- 保護者画面のコンパクト化は **保護者専用 CSS `.parent-compact-card`** に限定。講師画面へ波及させない。

### 予定登録・まとめて回答・過去・管理

- 予定登録はカレンダーの日付を複数選択して一括追加できる。日付の再タップで選択解除。種類/時間/場所を指定。時間プリセットと自由入力、終日がある。現在の選択肢は必ず HTML のラジオ群を参照。
- 予定登録時は `events` と `parentSchedules` をバッチで同時作成。公開予定の整合性を壊さない。
- まとめて回答は**本人の**複数活動の `○/△/×` を一括保存。
- 過去活動は月単位で取得し、月移動・種類絞り込み・月単位 CSV 出力に対応。必要に応じて月を選んで表示。
- 管理者は登録済みメンバー管理と一括削除が可能。一括削除は未来/過去などの絞り込み、対象選択、最終確認を経る。回答と公開予定データも処理する。大量削除は5イベント単位のバッチ/並行ワーカーによる最適化がある。削除は不可逆。

## 4. Firestore データとセキュリティ

主要コレクション：

- `members/{uid}`：承認済み利用者、名前、役割、順序、画像 URL 等。
- `accessStatus/{uid}`：役割確認用。権限の正本ではない。
- `userProfiles/{uid}`：登録待ちの表示名等。
- `events/{eventId}`：講師向け活動本体。
- `events/{eventId}/answers/{uid}`：本人の `○/△/×`。
- `events/{eventId}/childMemos/{memoId}`：子どものメモ（講師限定）。
- `parentSchedules/{eventId}`：保護者に公開する予定の最小データ。
- `parentSchedules/{eventId}/instructors/{uid}`：参加確定講師の公開用名前/画像。
- `places/{placeId}`：場所情報。

**認可の重要点**（`firestore.rules` を優先）：

- 保護者は `events`、`answers`、`childMemos`、全講師 `members` 一覧を閲覧できない。
- `answers` は本人 UID の書き込みが原則。管理者による削除権限は別途ルールで定義。
- `events` の新規登録は講師可、内容変更・削除は管理者。予定と公開予定の整合をルールで検査。
- `childMemos` は承認済み講師なら追加/編集/削除可。
- 公開予定の講師情報は参加回答 `○` などと一致する必要がある。公開用データは原本と分離する。
- ルールを変更するときはエミュレータ等で、管理者・講師・保護者・未承認者の読み書きを確認する。GitHub と Firebase 本番への反映を混同しない。

## 5. 通知（現行運用）

- スタッフ通知対象は登録済みの `admin` / `member` の**通知登録した端末**。保護者役割はスタッフ通知対象外。
- **予定登録時に自動送信しない。** 管理者が `📢 スタッフ全員に通知` を押し、確認ダイアログで承認したときのみ送信。
- 通知文言は **「活動予定を追加しました。」**。登録端末への Web Push。端末の OS/設定により通知音・バッジ挙動は異なる。
- iPhone は Safari からホーム画面に追加した PWA での通知利用を案内。Android は Chrome 等の対応環境。
- 初回通知登録を行う。登録済みなら登録ボタンは通常非表示となり、設定ボタンから再表示できる。端末変更時など未登録なら登録可能。
- iOS ではアプリ復帰時のバッジ消去処理あり。Android は通知バッジを勝手に消去しない設計。
- Worker は `kids-attendance-staff-push`。`push-test-sw.js`、`push-test-config.js` 等を削除しない。
- 以前、iPhone と Android の両端末に通知・バッジが届き、保護者への誤送信がないことを利用者が確認。**今後のすべての端末での成功保証ではない**。
- コードには過去の試験名称（`preview` / `test` / `parentPush`）が残る。**名称だけで本番不要と判断しない**。

- **2026-11-16 追加**：PC（Windows/Mac の一般的なデスクトップブラウザ）では通知登録パネルと「🔔 通知設定」ボタンを表示しない。スマホ・タブレットでは従来の通知 UI を維持。端末判定は User-Agent と iPadOS 判定を使うため、特殊なブラウザ環境では例外があり得る。通知送信処理・既存登録データ・出欠機能は変更しない。

- **2026-11-20 修正**：未来活動の出欠回答を各イベントの `answers` サブコレクションから取得し、**すべての対象イベントで初回回答スナップショットが届くまで**「未回答の活動があります」警告を表示しない。読み込み前の空データを未回答と誤認しない。活動カード上の「未回答」バッジも該当イベントの初回回答読込後に判定する。`loadedAnswerEventIds` をログアウト/再認証時にクリアし、対象イベントが消えたら対応する ID も除去する。回答の保存・編集権限は変更なし。実機での読み込み時間は未検証。

## 6. 過去に解決した不具合・再発防止

1. 出欠メモを活動詳細内に置くと、講師名とメモが一緒に開いた。→ メモの独立した開閉状態 `openChildMemos`、ヘッダーボタン `data-memo-toggle`、独立パネルを採用。講師詳細の開閉と連動させない。
2. メモボタンの配置が希望と異なった。→ **時間バッジの横・別枠**に修正。終日表示でも配置維持。
3. 保護者側に講師限定のメモが出る/出そうになった。→ `card(e)` の `parent` 分岐で非表示、ルールでも閲覧不可。保護者への情報漏えいを最優先で防止。
4. ステータス色の修正時、JavaScript の文字列/エスケープ不備で画面が壊れた。→ HTML テンプレートリテラル、正規表現、引用符、`<script type="module">` 内の構文を変更前後で検証。
5. アプリが「読み込み中」で止まった事例。再起動で復旧したことがあるが、**原因は確定していない**。レイアウト変更が原因と決めつけない。起動/認証/Firestore 読込の各段階を切り分ける。
6. Google 画像が変更直後に反映されない事例。→ ログイン状態での自動画像同期を実装。再ログイン後に反映したことを確認。Google/Firebase の画像情報反映には時間差があり得る。
7. 一括削除で件数が多いと遅かった。→ 現行コードに削除処理のバッチ最適化あり。ログイン・Firestore 購読を巻き込んで書き換えない。
8. 通知の試験版/本番版を整理した経緯あり。→ 現在使っている通知関連ファイルを名前だけで消さない。

3. 差分を最小限にする。UI だけなら原則 CSS/対象描画部分のみ。Firestore/通知/認証を不要に変更しない。
4. JavaScript 構文・テンプレート文字列・HTML の閉じタグ・CSS の適用範囲を検査。可能ならテスト/プレビュー後に本番反映。
5. 特に検証：①講師/管理者の活動と回答 ②保護者の公開情報のみ表示 ③出欠メモの独立開閉・編集 ④通知の対象と手動送信 ⑤過去・CSV・一括削除 ⑥iPhone/Android 表示。

7. コードと文書の両方を GitHub にコミット。変更したファイル、変更内容、検証結果、未確認事項をユーザーに伝える。
